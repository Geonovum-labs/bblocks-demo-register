# About this bundle

This is one OGC Blocks source directory, generated by ModelDesk from an
application profile. Copy it into a bblocks register repository, under
`_sources/`, in a directory named for the block:

    _sources/<group>/<block>/

## The identifier is the directory you choose

A block's `itemIdentifier` is never written in `bblock.json` — the postprocessor
builds it from the register's `identifier-prefix` (in `bblocks-config.yaml`) plus
the path under `_sources/`. So `myorg.p.` and `_sources/geo/point/` give
`myorg.p.geo.point`. Identifiers must stay stable once published, so choose the
directory before you submit rather than after.

## What to complete

- `examples.yaml` and `tests/` are scaffolds. bblocks validation is example-driven:
  until you write at least one, nothing checks the shapes this block ships.
- `version` and `dateTimeAddition` in `bblock.json` are defaults — `0.1` and the
  date the profile was created in ModelDesk. Set them to what the register should
  record.
- `status` starts at `under-development`. Raise it when the block is ready.

## The specifications this profile is derived from

`isProfileOf` names a profiled *block* by its register identifier, which a
specification's IRI does not determine — so this bundle lists the bases under
`seeAlso` instead of guessing:

- <https://semiceu.github.io/DCAT-AP/releases/3.0.1#>

If one of them is itself a registered block, move it out of `seeAlso` and
declare it: `"isProfileOf": "bblocks://<its identifier>"`. That is what makes
the register inherit its context and shapes.

## vocabulary.ttl

The profile defines terms of its own, and `vocabulary.ttl` holds their
definitions. It is declared twice on purpose: as a `resources` entry so the
register publishes it, and as a `shaclClosures` entry so those definitions are
present when your examples are validated — without the closure, an example
typed with one of these classes fails the shapes' own `sh:class` checks.

These terms are minted in the profile's own namespace. Publishing this file in
a register does not make that namespace resolve: hosting the IRIs is still
yours to arrange.
